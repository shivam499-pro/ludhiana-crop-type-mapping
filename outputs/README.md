## Current validation report

The current `accuracy_report.txt` uses
`data/P7_validation_predictions_rebuilt.csv` (292 held-out records). It reports
99.32% overall agreement, Cohen's Kappa of 0.9897, and this confusion matrix
(rows = true class, columns = predicted class; class order 1, 2, 3):

```text
[[98, 0, 0],
 [ 0,99, 0],
 [ 0, 2,93]]
```

The labels are phenology-derived, not independent field observations. These
metrics are agreement with the derived labels, not independent real-world or
field accuracy. No spatial-independence claim is supported by the coordinate-
free sample tables.

## Data sources and generation

Run `python scripts/accuracy_assessment.py` from the project root to regenerate
the report, confusion-matrix figure, NDVI chart, area chart, and area summary.
The script reads:

- `data/P7_validation_predictions_rebuilt.csv` for rebuilt predictions.
- `data/P7_area_stats.csv` for the existing class-area values.
- `data/monthly_ndvi.csv` for the NDVI chart if present; otherwise it uses the
  11 monthly values transcribed from GEE console output in the script.

The area figures and `area_summary.csv` are based on the existing area CSV and
have **not** been recalculated from the rebuilt classification raster. The
older `data/P7_validation_results.csv` contains 261 historical records and is
not the source for the current validation report.

The map PNGs are existing outputs from the earlier mapping workflow. The
rebuilt classified GeoTIFF export is configured for 10 m in EPSG:32643, but
that raster is not present in the current local project tree. The reported
rebuilt raster contains zero-valued pixels and has no explicit GDAL NoData tag:
zero is not a modeled class, and those pixels must not be interpreted as a
fourth crop class.
